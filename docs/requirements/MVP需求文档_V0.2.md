# 家语字幕屏｜家庭实时字幕 MVP 需求文档

> 文档版本：V0.2；产品首版仍为 V0.1 / MVP。  
> 日期：2026-11-09。状态：需求确认基线，尚未实现或实测。  
> 协作入口：[AGENTS.md](../../AGENTS.md)。本文替代原 V0.1 任务书作为当前需求基线，不自动授权开始开发或部署。

## 1. 目标与确认记录

为听力不佳的家人提供低操作成本、低延迟、大字号的实时字幕屏。Android Pad 在亮屏前台收音并显示字幕，服务端连接云端 ASR。首版为 Web 应用，不是 APK；开发验证从 Windows 开始，最终可脱离 Windows 通过云端服务使用。

体验优先考虑看得清、不中断、跟得上说话，同时必须满足意思可理解的准确性最低门槛。不能因界面顺畅、连接正常，就把经常意思相反的字幕判为可用。

### 1.1 已确认

用户在需求评审中的 1–6 项回复按六项完善建议落实；不视为对评审末尾六个信息问题的完整回答。

- 普通话、昆明话、上海话及自然混用是核心需求，不再描述成“普通话为主，偶尔混入方言”。默认不要求手动选择语言。
- 方言按原话显示，保留方言词语和语序，不翻译、不通过 LLM 改写成普通书面中文。标点与常规数字格式化可以使用，但不得改变意思；方言不同书写形式以家人能读懂为准。
- 正式应用实现前增加小规模真实家庭语音可行性验证。
- 首版基础验收关闭电视。电视开启可做探索性测试，不承诺自动排除电视人声。
- 接受按可见空间排版、有限回看、上翻不抢位置、临时字幕保持高对比的阅读方案。
- 准确性有最低门槛：核心使用者能理解主要意思；反复漏否定、错认关键数字/时间、导致意思反转时，不得宣布家庭可用。

### 1.2 建议默认值

以下为本版采用的可调整默认值，不代表实际设备或家庭习惯已经验证。

| 项目 | 默认值 |
|---|---|
| 日常人数与距离 | 2–4 人，讲话者距 Pad 约 0.5–2 米 |
| 字号 | 48 CSS px，可选 36 / 48 / 60 / 72 |
| 内存回看 | 最近 5 分钟，最多 300 条句子，先达到的上限生效 |
| 单次会话上限 | 120 分钟，同时受剩余每日额度限制 |
| 每日额度 | 开发 30 分钟；生产建议 120 分钟 |
| 首个识别候选 | 腾讯云实时 ASR V2；具体模型对比后决定 |
| 首版设备 | 一台 Pad，一个客户端占用一个上游识别会话 |

## 2. 范围与非目标

### 2.1 首版范围

- 开始/停止、实时临时字幕和定稿、大字号、全屏、回看、运行状态与错误恢复。
- 普通话、昆明话、上海话及混说的真实识别与分项验收。英文仅作补充测试，不替代方言。
- 浏览器内置麦克风优先，Windows 本地验证、Android HTTPS 验证、后续 Ubuntu 运行。
- 安全鉴权、有限重试、隐私保护、服务器端用量限制、Mock 模式和必要测试。

### 2.2 不在首版范围

- APK、后台常驻采音、开机自动录音、离线识别、Docker / Kubernetes。
- AI 问答、总结、翻译、语音播报、智能家居控制、LLM 补字或改写。
- 用户注册、复杂账号系统、历史录音检索、持久化逐字稿。
- 声纹注册、自动识别“爸爸/妈妈”、跨会话认人及人工身份纠错系统。
- 保证多人同时讲话都能完整识别，或自动隔离电视里的说话声。

识别讲话内容中提到的姓名、地名属于普通转写，不等于识别说话人身份。必要时可使用经用户许可的常用词表，不把真实家庭词汇硬编码进仓库。

## 4. M0 真实语音验证要求

1. 分别准备普通话、昆明话、上海话、混说四组，每组先约 20–30 句，覆盖主要家庭成员与自然语速。包含自发表达，不能只让一人朗读普通话稿件。
2. 基础环境关闭电视。记录麦克风、距离、服务、模型、参数和测试方式。电脑麦克风结果不能替代 Pad 收音验收。
3. 覆盖日常吃饭、出行、时间、金额、否定句及非敏感姓名/地名示例；无需保存真实家庭对话或原始录音。
4. 各组独立报告样本数、字错误率及方言书写归一规则、主要意思正确的句数、否定/时间/数字错误次数、需要重说的次数，并取得核心使用者阅读反馈。
5. 合理的方言异体写法单独记录；不能把翻译成普通话算作“原话正确”。各组不能用总体平均掩盖某一种语言失败。
6. 可以使用适用的官方演示或最小验证工具；若只测试了录音文件转写，结果只能作参考，不能证明实时 V2 链路可用。M0 不搭建完整产品或部署公网。
7. 小样本只筛查明显问题，不能证明长期高准确率。M0 后由用户与需求负责人确定各语言数值门槛；未经确认不得由实施 Agent 自行设宽松标准判通过。
8. 真实调用须有合法可用的测试凭据和明确小额用量上限。缺少权限、家人参与或设备时，先完成测试方案并报告依赖，不能用 Mock 代替结果。

## 5. 功能要求

### FR-01 启停与状态（P0）

- 初始不请求录音，大按钮显示“开始字幕”，提示“点击开始，显示身边的对话”。点击后申请麦克风权限；获准且上游连接成功后才显示“正在聆听”。
- 连接时防重复点击，不创建并发重复会话。无权限时不创建云端识别会话。
- 停止立即停采音、停上传、释放麦克风，后端发送云端正常结束消息。允许最多 3 秒接收已上传音频的尾句，然后关闭连接；超时保留已有文字并标记未定稿，不伪称定稿。
- 停止保留已有字幕与回看内容；再次主动开始、刷新或关闭页面清空。停止期间不因时间流逝自动清空。
- 标签关闭、页面退出时尽力释放资源，后端必须有心跳/空闲超时清理，不依赖客户端关闭事件。
- 状态覆盖未开始、请求权限、连接中、正在聆听、正在恢复、正在停止、已停止、错误。错误/停止后清理旧连接、采音回调与重试任务。
- 只有正常聆听状态向云端发送音频。权限申请成功不等于识别已开始。

### FR-02 字幕显示与回看（P0）

- 临时句逐步更新，以“识别中”等标记区分，保持与正文同等级可读对比度，不靠明显变浅区分。
- 同一句的修订覆盖原项，不反复新增。确定句稳定显示；支持重复、空文本、乱序、断线时的容错，不串会话。
- 按实际屏幕空间排版，不强制装下 3–5 句。长句换行，可滚动且不被底部按钮遮挡。
- 内存保留最近 5 分钟、最多 300 条句子；任一上限达到时淘汰最早内容。时间按采音会话时间计，停止后冻结；被淘汰内容不能回看，必要时提示“更早字幕已清除”。
- 仅在底部自动滚动；用户上翻后继续收音与接收文字，但不抢阅读位置，显示“有新字幕 / 回到最新”。
- 自动重连保留原字幕，在恢复处提示“连接中断，部分内容可能遗漏”。中断期间不补录、不缓存重放；主动重新开始才清空旧字幕。
- 不用 LLM 猜测漏识内容，不承诺完全消除 ASR 自身误识别。

### FR-03 适老化界面（P0）

- 横屏优先，深色背景与高对比浅色文字，默认 48 CSS px，提供 36 / 48 / 60 / 72 档，行高约 1.4–1.6。
- 控制项保持大且清晰：开始/停止、字号、全屏、查看上一句、回到最新。小屏不横向溢出，固定区域不遮正文。
- 状态用文字与图标共同表达，不仅依赖颜色；不显示 JSON、堆栈、密钥或完整服务器配置。
- 浏览器支持时保持屏幕常亮；失败提示调整系统息屏时间。只要求亮屏前台运行，锁屏/后台中断后明确提示并提供恢复入口。
- 字号等非敏感设置可存浏览器本地；音频与字幕不得存入本地持久化存储。
- 不在首版扩展多套主题；如实现已有深色偏好设置，可以保存。

### FR-04 麦克风与音频（P0）

- 使用浏览器 getUserMedia 和 AudioWorklet 等取得 PCM；根据实际设备采样率将 44.1k/48kHz 等转换为 16kHz、16-bit signed little-endian、单声道 PCM。
- 不假定 MediaRecorder 必定产生所需格式；验证采样率、字节序、声道、时长与下采样质量。
- 默认 200ms/包，即 6400 bytes，按 1:1 实时速率发送；40–200ms 可配置，最终按官方要求和真实稳定性确定，不批量高速回放。
- 无麦克风、拒绝授权、设备占用、断开或切换都有可理解提示。失败释放采集与云端会话，不只输出控制台错误。

### FR-05 云端识别与恢复（P0）

- 腾讯云实时 ASR V2 WebSocket 为首个候选，不用普通文件转写冒充实时识别。
- 可对比 16k_zh_en_2.0 与 16k_zh_en_speaker_2.0；优先保证核心字幕质量、延迟和费用，不把话者标签设为 M1 门槛。模型和事件差异由后端适配。
- 建议 voice_format=1、needvad=1、sentence_strategy=0；具体接口与支持范围以实施时官方文档和实际回包为准。
- 后端持有密钥并签名，前端不得得到 SecretKey 或完整腾讯签名链接。每次新建上游连接生成新 voice_id，不复用失效 ID。
- 句子定稿与整流结束分开处理：V2 sentence_type=1 表示句子确定，final=1 表示流结束，不能混用。
- 临时网络故障按 1s / 2s / 5s 最多三次重试；同一中断周期累计，不能因短暂握手成功不断清零。重试不重放旧音频。
- 鉴权失败、服务未开通、余额或资源不足不循环重试；失败提示“语音服务暂不可用，请联系管理员”。
- 麦克风断开清理资源；重试耗尽停止采集并提供“重新开始”；达到限额正常结束并说明原因。
- 上游支持语言不代表家庭效果合格。效果不足先报告，替换供应商须由用户决定。

### FR-06 隐私、安全与配额（P0）

- 采音状态持续显示麦克风标记，说明音频发送腾讯云识别，家庭成员知情后使用，一键停止。
- 本应用默认不录制文件、不存 PCM、不持久化逐字稿。后台日志禁止音频、识别文字、密钥和签名 URL，只记匿名会话、状态、耗时、错误码、用量等元数据。
- “应用不保存”不等于“供应商绝不留存”。真实调用前核对供应商数据处理说明；若测试确需临时保存真实音频/文字，另行取得许可、约定删除时间，不提交仓库。
- 密钥通过环境配置，.env 不提交，仅提供占位 .env.example。开发本地仅绑定 127.0.0.1；云端必须 HTTPS/WSS，有家庭访问鉴权、来源校验和并发限制，不开放匿名付费接口或非必要 CORS。
- 一次只允许一个客户端占用一个上游识别会话；第二个请求明确提示正在使用，不偷偷抢占。
- 服务端强制单次和每日时长额度。开发默认每日 30 分钟，生产建议每日 120 分钟，单次默认 120 分钟；服务器验证，不只靠前端倒计时。
- 每日以 Asia/Shanghai 自然日重置；跨午夜按实际时段分摊。可持久化无内容的用量元数据，重启不清零、不绕过限额。
- 时长配额不是账单绝对封顶。静默期间持续上传也计入应用用量，不假定只有有效讲话才收费。

### FR-07 Mock 与可测试性（P0）

- ASR_PROVIDER=mock|tencent；Mock 无需云端密钥，不访问云服务、不产生 ASR 费用。
- 模拟临时→修订→定稿、空文本、重复、乱序、断线、重试耗尽、未知角色、停止尾句等。
- 有针对性测试字幕归并、状态清理/重连、音频格式与配额。文档、简单样式修改不为凑数量增加测试。
- Mock 不作为真实准确率、时延、Pad 收音或供应商费用证据。

## 6. 最小技术基线与接口约束

- 原生 HTML/CSS/JS + Python FastAPI；Windows 与 Ubuntu 使用同一应用代码和环境配置，少依赖、便于排障。
- 浏览器负责采音、转换、显示；后端负责鉴权、配额、上游适配与生命周期；不得把云端密钥放进浏览器。
- HTTP：GET / 页面；GET /health 仅返回非敏感健康状态。WebSocket：/ws/live。
- 浏览器发送 start（含 client_session_id）后发送二进制 PCM，不用 JSON + Base64 包音频；stop 由后端转换为上游 end。
- 后端统一发 status、transcript、error、usage。transcript 至少含 session_id、sentence_id、text、is_final，可带 speaker_id、start_time_ms、end_time_ms。
- 应用 transcript.is_final 仅表示该句定稿。前端以 session_id + sentence_id 归并；每个新上游连接使用新 session_id，自动重连保留旧显示并隔离旧事件。
- 旧连接迟到消息不得修改新会话；新 session 的状态先于其字幕，不能因收到任意陌生 session 消息就覆盖当前状态。
- 预留 speaker_id 即可；如果直接显示上游标签，未知时隐藏或显示“说话人待确认”，不猜姓名。重连不保证编号对应原人，不扩展声纹上下文持久化。
- 输入长度、消息频率和连接数有上限；解析错误应产生可理解提示，不能无声卡死。
- 建议结构：app/（服务）、static/（前端）、tests/、docs/、scripts/（必要验证工具）、requirements.txt、.env.example。无需为目录形式过度拆模块。

开发 Agent 在多个实现者并行前固化接口字段和状态语义；这些实现细节可以在需求范围内自行决定，并记录在技术文档。改变用户行为或验收范围则回到需求确认。

## 7. Windows、Android 与 Ubuntu 约束

### Windows / M1

- Python 3.11+，Chrome/Edge；先 Mock，再短时真实链路，最后 15 分钟说话与静音混合运行。
- localhost 可用于本地采音验证；开发模式只绑定回环地址。
- 检查停止、再次开始、断网、关闭标签、权限拒绝和残留会话；日志与仓库不出现密钥和家庭内容。
- 提供实际验证过的启动命令，不把尚未运行的示例命令说成成功记录。

### Android / M2

- getUserMedia 要求安全上下文，不把 http://192.168.x.x 当作正式采音方案。
- 使用 Pad 信任的 HTTPS；不关闭浏览器安全检查、不以忽略证书错误验收。
- 测试实际 Pad 横屏、所有字号、阅读距离、内置麦克风、常亮、30 分钟持续使用和 0.5/1/2 米收音。
- 三种语言及混说分别测；关闭电视作为基础，电视开启单独标为探索。
- 若 30 分钟稳定性测试需加前置调试时长，应预先在任务授权内明确临时测试额度；不能偷偷移除服务器限额。

### Ubuntu / M3

- 在授权范围内使用私有仓库、非 root 服务用户、虚拟环境、systemd；应用绑定回环端口，复用现有 Caddy/Nginx 等反代，避免端口冲突。
- HTTPS/WSS、鉴权、长连接、服务重启后的配额均须验证；Windows 关机后 Pad 应可使用。
- 提供安装、启动/停止、状态/日志查询、密钥更新、版本发布、回滚、用量查询说明。发布记录 Git 提交和实际验证结果。
- 实际部署前确认服务器地区、网络、域名及相应服务可用性；不假设境外调用适用同样的开通条件和价格。

## 8. 成本口径

原 V0.1 以约 ¥1/小时估算腾讯云 ASR，作为历史规划参考，不作为本版已复核报价或费用承诺。真实调用前核对所选模型、账号、地区、资源包/后付费、话者分离增值项与服务器流量；记录来源、日期和计算口径。

- 默认限制以累计上游音频时长计，不以“说了多少话”计；控制台账单为结算依据。
- 16kHz × 16bit × 单声道约 32 KB/s，单段传输约 115 MB/小时；中转涉及两段网络，另计协议开销。
- 如显示估算费用，必须标记“估算”并使用可追溯单价；价格未确认时只显示时长，不虚构金额。
- 月度预算待用户确认；不自行购买资源、开启不受控后付费或采购设备。

## 9. 验收标准

### 9.1 目标与判定

| 项目 | 目标/要求 | 证据 |
|---|---|---|
| 首字延迟 | 争取 P95 ≤ 1.5s | 至少 30 句，说明发声起点测法、样本数、误差与各语言情况 |
| 停顿后定稿 | 争取 P95 ≤ 2.0s | 句末至确定字幕显示，记录方法与样本 |
| 普通话准确度 | 安静环境参考 CER ≤ 10%，同时意思可理解 | 人工参考、归一规则、错误统计 |
| 昆明话/上海话/混说 | 分别满足 M0 后确认的门槛 | 各组独立结果；未测试或门槛未确认不得判通过 |
| 核心意思 | 不反复出现否定/关键数字错误或意思反转 | 错误次数和核心使用者反馈，不用总体字准率掩盖 |
| 稳定性 | Windows 15min / Pad 30min | 说话与停顿混合，记录断线、重试与残留会话 |
| 阅读 | 字体可读、不遮挡、回看不被抢位 | 实际设备与核心使用者反馈 |
| 隐私/安全 | 未授权不采音、停止不上传、无内容日志和密钥泄漏 | 权限、网络与日志检查 |
| 配额 | 服务端硬限制，重启不清零，北京时间重置 | 用短配额或模拟时钟验证，无需浪费数小时真实用量 |

目标值尚非测得结果，也非供应商 SLA。达不到时报告偏差，不能自行调整标准后称通过。

### 9.2 必测行为

- Mock 无密钥可运行且无云端调用；真实测试与 Mock 分开记录。
- 重复/乱序/空结果不重复定稿、不串会话；临时字持续更新且清楚可读。
- 停止立即释放麦克风，尾句可收完或明确超时；再次开始清空旧字幕。
- 上翻继续收音且不抢位置；回到最新有效；缓存按时间和条数有界。
- 断线有限重试，新 voice_id/session_id，原字幕保留并标记遗漏；无音频重放。
- 拒绝权限、麦克风断开、鉴权/余额错误均明确提示并清理资源。
- 刷新/关闭标签后后端及时清理，不留下持续计费会话。
- 单客户端并发限制、访问鉴权、日志脱敏、配额重置与重启恢复均有效。
- Android 四档字号、长句、控制栏、常亮与前台限制验证。
- Windows 关闭后云端服务可独立使用（仅 M3）。

### 9.3 每阶段报告

报告区分：已验证通过、已验证失败、未验证、待用户验收。记录阶段、版本/提交或工作区状态、环境、具体步骤、实际结果、缺陷与下一步建议。无证据时不能填写“通过”。

不把真实家庭文字/音频放入报告；使用匿名汇总或经许可的非敏感测试例句。截图、测试输出和提交前均检查是否包含密钥、签名链接、家庭内容。
