# M1 接口约定（前后端消息契约与状态语义）

> 依据需求 §6“最小技术基线与接口约束”固化。实现细节可在需求范围内调整，改变用户行为或验收范围需回需求确认。
> 实现位置：后端 `app/main.py`（WebSocket 处理）、`app/session.py`（生命周期）；前端 `static/app.js`、`static/merge.js`。

## 1. HTTP

| 接口 | 鉴权 | 说明 |
|---|---|---|
| `GET /` | 访问码 | 字幕页。`?token=<ACCESS_TOKEN>` 首次进入后写 HttpOnly Cookie `familyasr_token`（30 天）；无码返回 401 访问码输入页 |
| `GET /health` | 无 | `{"status":"ok","provider":"mock|tencent"}`，仅非敏感健康状态 |
| `GET /static/<path>` | Cookie | 前端静态资源（同样需要访问码） |

访问码经 Cookie 或 `?token=` 提交，比较用 `hmac.compare_digest`；任何响应不回显访问码。

## 2. WebSocket `/ws/live`

- 鉴权：Cookie 或 `?token=`；无码/错码在 accept 前以 4401 关闭。
- 来源校验：浏览器请求的 `Origin` 必须与 `Host` 同源（跨站 WebSocket 劫持防护），否则 4403 关闭。
- 文本帧为 JSON 控制/事件消息；二进制帧为 PCM 音频（16kHz / 16bit signed LE / 单声道 / 200ms 一包 = 6400 字节，1:1 实时速率）。
- 不用 JSON+Base64 传音频。

### 2.1 客户端 → 服务端

| 消息 | 说明 |
|---|---|
| `{"type":"start","client_session_id":"<uuid>"}` | 请求开始识别。防重复：会话进行中返回 busy |
| `{"type":"stop"}` | 请求停止：立即停采音，后端转上游 end，最多 3 秒尾句 |
| `{"type":"ping"}` | 心跳（前端每 5 秒）。后端 30 秒无任何消息即判定闲置并清理 |
| `{"type":"usage"}` | 请求用量快照 |
| 二进制 | PCM。仅会话“聆听”状态接受；未开始时返回 not_started 错误 |

### 2.2 服务端 → 客户端

| 消息 | 字段 | 说明 |
|---|---|---|
| status | `state, session_id, detail, speaker_labels?` | `connecting / listening / recovering / stopping / stopped / error`；`session_id` 为上游连接 ID，每次（重）连接更新；`speaker_labels` 仅连接就绪的初始 status 下发（V0.2 标签显示开关，见 §2.4） |
| transcript | `session_id, sentence_id, text, is_final, speaker_id, start_time_ms, end_time_ms` | `is_final` 仅表示该句定稿（上游 sentence_type=1）；与上游 `final=1`（整流结束）不混用；`speaker_id` 见 §2.4 |
| error | `code, message, recoverable` | 可理解提示；不出现堆栈/密钥/签名 URL/识别文字 |
| usage | `session_seconds, daily_seconds, daily_limit_seconds, session_limit_seconds` | 仅时长（费用未确认前不虚构金额） |
| pong | — | 心跳应答 |

### 2.3 会话隔离与归并

- 前端以 `session_id + sentence_id` 为键归并（`static/merge.js`）：同句修订覆盖原项，定稿后冻结；空文本、重复、乱序短文本容错；不同 session_id 互不影响（不串会话）。
- 自动重连（后端→腾讯云）产生新 session_id 与新 voice_id；旧显示保留，旧连接迟到消息不修改新会话。
- 重连期间不补录、不缓存重放音频。

### 2.4 说话人标签（V0.2；详见 V0.2-说话人能力核验.md）

- `speaker_id`（transcript 字段）：**有效取值 `0–9`（`0` 是有效值），`-1` = 未知**（缺失/非法一律规范为 -1）。后端（腾讯适配与 Mock）在发出前规范化，前端归并时同规则防御。
- 标签修订规则：未定稿句允许 `-1 → 有效 ID` 的标签补全；`-1` 不撤回已知有效 ID；**定稿后文字与标签一起冻结**，不为标签解冻。一句话只归属句级 `speaker_info`；词级标签不使用，无法可靠归属 → 未知，不强归某人。
- 匿名编号：前端 `SpeakerNamer` 按 `session_id`（=上游连接）把有效上游 ID 映射为“说话人 1/2/…”（首见顺序，仅内存保存）；同一有效 ID 在同一连接内编号稳定。未知显示“说话人待确认”，不沿用上一位标签。
- 重连后新连接重新编号，前端提示“连接已恢复，说话人编号重新计算”；新旧连接相同编号不表示同一人。
- 显示开关：初始 status 的 `speaker_labels`（服务端 `SPEAKER_LABELS`，默认 on）。**off=仅隐藏标签**（模型与文字不变）；**切回无标签基线**用 `ASR_ENGINE_MODEL_TYPE=16k_zh_en_2.0`——两者效果不同，不得混淆。
- 标签为文字标签（不只靠颜色区分），不挤占正文主要空间；大字号、全屏、回看与上翻行为不变。

### 2.5 错误码（应用层）

| code | 含义 | recoverable |
|---|---|---|
| busy | 已有会话/其他设备占用 | 是 |
| not_started | 未开始就发音频 | 是 |
| protocol | 消息无法解析/未知类型 | 是 |
| quota_daily / quota_session | 服务端硬配额触发，会话正常结束 | 否 |
| idle_timeout | 心跳超时，自动清理 | 否 |
| upstream_interrupted | 上游瞬断，自动重试中（字幕可能遗漏） | 是 |
| upstream_<code> | 腾讯云错误码映射（4002-4005 统一“语音服务暂不可用，请联系管理员”） | 否 |
| upstream_unavailable | 重试耗尽 | 否 |
| internal | 服务内部错误（无细节） | 否 |

## 3. 生命周期与清理（FR-01）

```
idle → [点击开始] → 请求麦克风权限(前端) → connecting → listening ⇄ recovering
     → [点击停止] → stopping（停采音→上游 end→3s 尾句）→ stopped
任意阶段错误 → error（清理采音/连接/重试任务后可重新开始）
```

- 获得麦克风权限后才建立 WebSocket/云端会话；权限失败不创建识别会话。
- 前端仅 listening 状态发送 PCM；停止/出错立即释放麦克风（MediaStreamTrack.stop）。
- 后端不依赖客户端关闭事件：心跳 30 秒闲置清理 + WebSocket 断开即 abort（取消上游任务、释放连接、落盘用量）。
- 停止保留字幕与回看；再次主动开始/刷新/关闭页面才清空。

## 4. 用量与配额口径（FR-06）

- 以浏览器实际上传的音频时长累计（1:1 实时率下=上游音频时长；静默上传也计入）。
- 单次与每日限制均为服务端强制（默认 120 分钟/次、30 分钟/日，可在 .env 调整）。
- 剩余每日额度不足一包音频（200ms）时不允许开始会话（quota_daily 拒绝）。
- 每日按 Asia/Shanghai 自然日重置；用量元数据持久化于 `var/usage.json`（仅日期+秒数，无内容），重启不清零。

## 5. 音频格式（FR-04）

- 浏览器 `getUserMedia` + `AudioWorklet` 采音，按上下文实际采样率（44.1k/48k 等）下混单声道后线性插值重采样至 16kHz、16bit signed LE。
- 200ms/包（6400 字节）以 1:1 实时速率发送；不批量回放。
