# 产品 V0.2：多人轮流讲话与匿名说话人标签任务书

> 日期：2026-11-10。当前状态：任务书已制定，实施与阶段验收尚未完成。
> 需求基线：[MVP 需求文档 V0.2](../requirements/MVP需求文档_V0.2.md)。本文的产品 V0.2 与需求文档版本号是不同概念。

## 1. 决策与授权来源

用户反馈“已经完成上云，测试也完成了”，希望从多人语音识别开始；在建议先做“多人轮流讲话＋匿名说话人标签”的小规模验证后，用户回复“可以。帮我完成该阶段任务书”。本轮完成阶段定义与任务书，不据此自动修改应用、调用收费服务或发布云端版本。用户将本任务书交给实施 Agent 执行时，作为以下实施范围的依据。

用户反馈作为最新进展保留；现有云端部署记录见 [M3 云端部署说明](M3-云端部署说明.md)。既有阶段说明仍有历史状态，实施开工时应结合已有记录及用户反馈同步；不得把“测试完成”补写成所有语言、Pad 时长、性能指标均已通过。缺少的分项证据只列为待补充，不要求无理由重跑已有测试。

## 2. 目标与边界

目标：让家人阅读多人对话时更容易判断当前字幕属于哪位讲话者，先验证两人轮流讲话，再扩展到 3–4 人。保持原有原话转写、可读性、稳定性与延迟要求。

本阶段包含：

- 核验现有腾讯云实时链路的说话人标签能力，进行有标签与现有基线的对比。
- 在同一次上游识别连接内显示“说话人 1 / 2 / …”，未知显示“说话人待确认”。编号仅作匿名区分。
- 必要的后端字段适配、前端归并与标签显示、Mock 与核心回归测试。
- 真实 Pad 上两人及 3–4 人验证、三种语言与自然混说分项记录、家人阅读反馈。
- 快速接话、短句插话、短暂重叠作为专项测试；重叠效果单列，不承诺完整识别。

不包含：姓名或家庭身份识别、声纹注册、跨连接认人、人工身份纠错系统、独立音源分离、保证多人同时讲话完整转写、电视人声过滤、LLM 补写、录音或逐字稿持久化、更换供应商、采购设备。继续使用 Web + FastAPI，不扩展复杂基础设施。

## 4. 执行顺序与进入条件

### A. 盘点与能力核验

1. 读 AGENTS、需求基线、本任务书，检查工作区和部署版本。确认实际当前模型与参数，读取配置时不输出凭据。
2. 查腾讯云最新官方文档，记录链接、查阅日期、实时接口与模型、标签返回层级、未知值、支持语言、临时/定稿与后续修订行为。现有 speaker_id 传递代码只表示已有接线，不证明真实能力通过。
3. 核对所需权限、增值收费与计费方式。不得根据模型名称或旧示例直接替换模型。若需要新付费开通、更换供应商或突破已有用量授权，先提交具体能力差异、费用和测试用量方案供用户决定。
4. 明确与现有基线的对比配置及有限真实测试用量。凭据仅后端环境读取，保持每日与单次硬配额。家庭成员参与和知情、实际 Pad、测试额度是实测依赖。

能力不支持或关键依赖缺失时，完成核验和独立验证并报告；不得用虚构标签包装成可用，不因此自行扩大技术方案。

### B. 固化契约并完成最小实现

- 保持现有 transcript 的 session_id、sentence_id、text、is_final 等语义；speaker_id 缺失或非法时规范为未知，有效值 0 不得被误判为空。
- 编号映射按上游连接隔离，只在内存中保存；同一有效上游 ID 显示同一匿名编号，不能以语言、文本内容或轮次猜测身份。
- 明确一句内多位说话人、词级标签等实际返回如何处理；无法可靠归属时标未知，不强行把整句归给某人。若需拆句，先在契约中约定稳定键与修订规则，避免重复字幕。
- 明确定稿文字和标签的更新规则。只有官方协议和实测支持的修订才处理；不能为接收标签而任意解冻所有定稿文字。
- 自动重连保留旧字幕，提示“连接已恢复，说话人编号重新计算”，新旧连接的相同编号不表示同一人；旧回包不得修改新连接字幕。
- 标签保持清晰但不挤占正文主要空间，不只靠颜色区分；未知不沿用上一位标签。保留大字号、全屏、回看与上翻不抢位。
- 提供可逆配置以恢复既有无标签模式；说明是仅隐藏标签还是切回原模型，不能混淆两者效果。
- 保持停止立即停采集上传、尾句上限、鉴权、单会话限制、持久化配额和无内容日志。

### C. 验证与比较

先自动化验证，再进行现有额度内的真实短测；达到候选可用后做实际 Pad 连续使用。正式云端发布前交付可审阅差异、回滚方式与验证结果，发布、提交、推送以当轮明确授权为准。

## 5. 测试矩阵与记录口径

以下是建议起始样本量，用于暴露明显问题，不是统计保证或通过阈值。实际不足须记录原因。

| 场景 | 起始样本与检查点 |
|---|---|
| 单人基线 | 标签是否把同一人频繁拆成多人；比较文字质量与延迟 |
| 两人轮流讲话 | 普通话、昆明话、上海话、自然混说各至少 20 个明确归属话轮，覆盖双方 |
| 快速接话与短句插话 | 至少 20 个交接点；观察漏句、归错人及临时标签跳变 |
| 3–4 人轮流讲话 | 至少 30 个话轮且每人参与；观察合并不同人、拆分同一人 |
| 短暂重叠 | 至少 10 次，单列遗漏和归属错误，不与轮流讲话平均掩盖 |
| 位置与距离变化 | 实际 Pad 约 0.5/1/2 米，记录环境、位置及收音变化 |
| 连续使用 | 候选配置实际 Pad 前台 30 分钟，说话与静音混合；记录断线与编号变化 |
| 生命周期与回归 | 停止尾句、再次开始、断线重连、旧回包、权限失败、限额与并发拒绝 |

关闭电视作为基础环境。比较现有配置与候选配置时保持相近设备、距离、语言和话轮任务；顺序测试注明非同一音频及误差，不为公平比较擅自录制家庭对话或创建并发收费会话。

现场观察者用匿名 A/B/C/D 标记真实说话人，在每个连接内对齐系统编号。编号数值不同不是错误；对齐后归错人、同人被拆分、多人被合并、未知分别统计。对齐规则先确定，不能逐句重映射掩盖跳变。

报告至少记录：

- 每组话轮总数、标签正确/错误/未知数、同人编号跳变次数；未知计入覆盖率分母，不能只报已识别人群的准确率。
- 文字主要意思正确数、关键否定/数字/时间错误、漏句和重说次数；各语言及混说分别汇总。
- 首字、定稿和标签首次可用延迟，说明测法、样本数与误差；报告 P95 时至少 30 个有效测量样本，样本不足不伪称达标。
- 连接中断、错误恢复、停止残留、用量；费用仅使用真实可追溯账单或明确标注来源的估算。
- 核心使用者是否更容易跟上对话、标签是否造成误导、字号及阅读空间是否受损。

只保存匿名统计与非敏感测试数据；真实对话文字、音频、截图不进入仓库或报告。确需保存时另行约定许可、用途和删除时间。

## 6. 验收与退出

技术交付必须满足：契约与实现一致、未知安全处理、连接隔离、无重复字幕、关键生命周期与安全配额回归通过、能够恢复既有配置。Mock 覆盖缺失/非法/零值 ID、标签修订、重复与乱序、停止尾句及重连，测试具体规则而非机械复写实现。

产品验收由用户与需求负责人决定：在各核心语言文字质量及既有要求保持的前提下，匿名标签是否提高实际阅读体验。现有延迟目标仍作比较依据，不能因新增标签自行放宽。标签准确率、未知比例和稳定性的数值门槛在首轮真实结果后提交用户确认；未确认前只能称“探索验证完成”，不能称“产品 V0.2 验收通过”。

退出结论允许为：建议启用、继续局部修正后复测、当前方案不适合启用。均需给出证据；不合格时保留已知可用配置，不隐藏失败、不自动换供应商。
