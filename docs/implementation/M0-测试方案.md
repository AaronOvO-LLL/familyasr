> 状态：**已完成**（2026-11-09 准备稿；2026-11-10 用户安排家庭实测并确认通过，结论见 [M0-验证报告](../reports/M0-验证报告.md)）。

## 1. 目标与证据边界

### 1.1 目标

用小规模真实家庭语音，回答一个问题：**腾讯云实时语音识别 V2 对普通话、昆明话、上海话及自然混用的识别效果，是否达到“核心使用者能理解主要意思”的底线**，并筛查明显缺陷（否定、数字、时间、意思反转）。同时记录模型、环境、用量与阅读反馈，为 M0 后确定数值门槛提供依据。

### 1.2 证据边界（写入 M0 报告时必须原样保留）

| 测试方式 | 能证明 | 不能证明 |
|---|---|---|
| probe `--input wav`（文件送实时 V2 通道） | 实时 V2 链路可用、识别效果 | 麦克风采集质量、现场收音 |
| probe `--input mic`（电脑麦克风） | Windows 端全链路 | **Pad 收音、Android 阅读体验（须 M2）** |
| 云端 Web 应用（asr.hao-rizon.com，Pad/PC 浏览器） | 真实实时链路 + 字幕归并 + 核心使用者当场阅读反馈 | 与 M2 重叠部分可顺带记录，但 **M0 结论不依赖 Pad 验收**；Pad 收音/30 分钟稳定性仍以 M2 为准 |
| 任何 Mock | 工具逻辑 | 真实准确率、延迟、费用 |

- M0 只筛查明显问题，小样本不能证明长期高准确率。
- 各组独立报告，不用总体平均掩盖任何一种语言的失败。
- 录音文件转写接口（非实时 V2）的结果即使做，也只能作参考，不证明实时链路。

**D3 核对结论（2026-11-10，来源：腾讯云官方文档）：**

- 《语音识别服务条款》（cloud.tencent.com/document/product/301/94121）：数据处理地点为中华人民共和国境内；腾讯云仅在提供服务所必需期间内保留数据，期限结束后删除或返还；输入素材含个人信息需取得主体知情同意（家庭测试句为非敏感测试内容，参考文本为方言原话，注意不录真实敏感对话）。
- 同条款 2.11：为**问题排查与分析**目的，腾讯云可能使用问题数据（识别错误/失败等）及上传的音频信息；**可通过联系售后支持撤回该授权**（撤回前已处理的不受影响）。
- 官方 FAQ（cloud.tencent.com/document/product/1093/35802）：语音内容仅供当次识别使用、不会保存；识别成功后保存的文本文件在服务器保留 7 天。
- **综合结论**：“应用不保存”≠“供应商零留存”：常规识别不留存音频；但问题排查场景可能留存问题音频（可撤回授权）、识别文本服务器端保留 7 天。对 M0 测试句（非敏感）可接受；正式家庭使用前若在意，建议联系售后撤回问题数据授权并记录。本结论写入 M0 报告时按原文保留，不得简化为“供应商不留存”。

## 4. 样本设计

### 4.1 总体安排

- 四组独立：**普通话、昆明话、上海话、混说**，每组 **24 句**（20–30 句区间内取 24）。
- 说话人：每组至少 2 名说话人，覆盖家庭主要成员（Q1 未确认时按 2–4 人轮换）；自然语速，不刻意放慢。
- 说话方式配比（每组）：
  - **自发表达 8 句**：只给话题卡，说话人用自己的话自然说；
  - **要素指定句 10 句**：指定必须包含的要素（见 4.2 矩阵），句式由说话人自己组织，**不照读普通话稿件**；
  - **对话截取 6 句**：两人自然对话 1–2 分钟，事后从中取 6 句（用对话原话作参考文本）。
- 基础验收**关闭电视**；每句之间自然停顿 1–2 秒。
- 混说组：按家庭真实习惯在句内/句间自然混用普通话与方言，不摆拍式“一半普通话一半方言”。
- 方言组的参考文本是**方言原话**（家人书写，以家人能读懂为准），不是翻译成普通话；翻译不算正确。

### 4.2 要素覆盖矩阵（每组 24 句的构成）

| 要素类别 | 句数 | 说明与示例（示例仅示意要素，非照读稿件；姓名/地名均为非敏感占位） |
|---|---|---|
| 吃饭 | 3 | 例：「小明，晚饭想吃米线还是饭？」 |
| 出行 | 3 | 例：「明天早上九点从人民路坐车去火车站。」 |
| 时间 | 3 | 必含具体时刻/时长：「下午三点二十提醒我吃药」「等了大概半个小时」 |
| 金额 | 3 | 必含具体数字：「这个月电费一百八十六块」「菜钱一共花了三十二块五」 |
| 否定句 | 3 | 必含否定/禁止：「我没关窗户」「别忘了带钥匙」「外面没下雨」 |
| 姓名/地名 | 3 | 非敏感示例：小明、小红、王老师、人民路、翠湖；**不得使用真实家庭成员姓名与常用真实地名以外的隐私信息** |
| 自由话题 | 6 | 话题卡：家常闲聊、提醒、商量、感叹；其中 ≥2 句含否定，≥2 句含数字 |

- 指定要素句（时间/金额/否定）在每组至少覆盖**否定 4 句、数字 4 句、时间 3 句**（与上表可重叠），确保 §9 的“意思反转”风险句足够。
- 话题卡（自发表达/对话用）：吃饭商量、明天出行安排、提醒吃药/带东西、算一笔小账、回忆一件小事、对某事表示不同意/没关系。

### 4.3 执行顺序（控制疲劳与顺序效应）

1. 普通话组（校准流程，熟悉标记与记录）→ 2. 混说组 → 3. 昆明话组 → 4. 上海话组；
4. 如需对比 `16k_zh_en_2.0` 与 `16k_zh_en_speaker_2.0`，只在普通话组 + 方言表现最差的一组上做，避免用量翻倍。
- 同一说话人不连续说超过 12 句；核心使用者在场观看字幕并当场反馈（§7 表 E）。

## 5. 测试工具与操作

工具：[`scripts/m0_realtime_probe.py`](../../scripts/m0_realtime_probe.py)（腾讯云实时 ASR V2 最小验证工具；仅标准库，mic 模式需 sounddevice）。

```bash
# 0) 密钥：复制 .env.example 为 .env 填入（.env 不入库、不外发）
# 1) 先做不联网自检
python scripts/m0_realtime_probe.py --dry-run
# 2) WAV 模式（链路校准，30 秒即可；注意 §1.2 证据边界）
python scripts/m0_realtime_probe.py --input wav <测试.wav>
# 3) 麦克风模式（M0 主路径）；--mark 开启后，说话前按一次回车记录发声起点
python scripts/m0_realtime_probe.py --input mic --seconds 120 --mark
```

- 输出只到控制台，**工具不保存音频与识别文本**；测试员把定稿句实时抄入 [M0-结果记录表](M0-结果记录表.md)（测试句为非敏感测试内容，参考文本可保留；原始音频不保留）。
- 对话截取段用 `--seconds 120` 一次录制，两人自然对话。
- 出现错误码时工具给出可读提示（见需求文档 FR-05；鉴权/欠费/资源不足类**不重试**，先解决再测）。

## 6. 指标定义与归一规则（每组独立计算）

| 指标 | 定义 |
|---|---|
| 样本数 N | 该组有效句数（说话被打断/设备故障的句标为无效并注明） |
| 字错误率 CER | 对每句：归一后按字计算 (替换 S + 删除 D + 插入 I) / 参考字数；组内报各句 CER 与总 CER |
| 主要意思正确句数 | 核心使用者判定“听/看懂主要意思”的句数（Y/N） |
| 否定错误次数 | 否定词丢失、否定变肯定、意思反转（每句计 1 次） |
| 数字错误次数 | 金额/数量听错（每个错误数字计 1 次） |
| 时间错误次数 | 时刻/时长听错（每次计 1 次） |
| 需要重说次数 | 该句首次显示后核心使用者要求重说的次数 |
| 首字延迟（可选） | 发声起点（probe 回车标记）→ 首个临时句显示 |
| 定稿延迟（可选） | 句末 → 定稿句显示；目标 P95 ≤1.5s / 2.0s 为“争取目标”，非承诺 |

**归一规则（先登记、后计分，登记表在结果记录表 §归一）：**

1. 去标点、空白；繁简统一（以简体为准）。
2. 数字格式统一后比较：“三点半”与“3点半”等价；但**数值说错算数字错误**，格式归一不掩盖语义错误。
3. 方言异体写法：以家人能读懂的写法为准，登记「异体写法 → 归一写法」映射，映射内写法均计正确；**不得把翻译成普通话算作原话正确**。
4. 语气词、口语重复（“那个那个”）按识别是否影响主要意思判定，不机械计错。
5. 归一规则在测试前由测试员 + 家人共同确定并登记，测试中途不改口径；如需修改，记录修改时间与原因。

## 8. 用量与成本控制

- **计费口径**：按累计上游音频时长计（含静默），不按“说了多少话”计；以腾讯云账单为结算依据。
- **价格记录**（来源：腾讯云《计费概述（在线版）》，页面更新 2026-10-29，本方案 2026-11-09 查阅；实施前须复核）：

| 项目 | 数值 | 备注 |
|---|---|---|
| 实时语音识别（大模型 2.0 版）后付费 | **1.0 元/小时**，日结，无用量梯度 | M0 首选引擎即此计费体系 |
| 实时语音识别（大模型 2.0 版）预付费 | 60 小时 / ¥60（1.0 元/小时） | 更大包单价降至 0.85–0.95 元/小时 |
| 实时语音识别（大模型 1.0 版）后付费 | 4.80 元/小时起（0–299 小时/日） | 对比用 |
| 免费额度 | **大模型 2.0 版无免费额度**；非大模型“实时语音识别”每月 5 小时 | 不要指望免费额度覆盖 M0 |
| 后付费开关 | 新用户默认**关闭**；资源包耗尽自动停服 | **不要**为测试方便开启不受控后付费 |

- **用量预算（估算，标记为估算）**：一轮全量 ≈ 4 组 ×（24 句 + 2 分钟对话）≈ 40 分钟；引擎对比 + 复测余量 ×2 ≈ 80–120 分钟。按 1.0 元/小时估算 **≤ ¥2**（估算值，实际以账单为准；价格未复核前不对外显示金额）。
- 执行前由用户给出**明确的小额上限**（建议：不超过 2 小时音频时长 / ¥5），达到上限立即停止。
- 不自行购买资源包、不开启后付费、不采购设备（Q4 未决定前不买外接麦克风）。

## 9. 判定纪律（防“改宽标准藏失败”）

1. M0 后由**用户与需求负责人**确定各语言数值门槛；实施方不得自行设宽松标准判通过。
2. 每组独立结论：`可用 / 有明显问题 / 不可用`，附证据（表 B/C/D + 阅读反馈）。
3. 出现反复否定反转、关键数字/时间错误导致意思相反 → 不得宣布“家庭可用”，如实报告。
4. 报告区分：已验证通过 / 已验证失败 / 未验证及原因 / 待用户验收；无证据不填“通过”。
5. 真实家庭对话内容、原始音频不进报告与仓库；示例句只用非敏感测试句。
