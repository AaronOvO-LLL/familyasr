## 已验证通过（实际运行）

1. 签名/URL：参数字典序拼接、HMAC-SHA1+Base64、urlencode 拼回；独立复算一致；voice_id 每次唯一；密钥不进 URL。
2. 识别结果解析：兼容官方 SDK 的 `sentences.sentence_list[]` 与 `sentence` 字段，兼容 list/`text` 变体。
3. 归并语义（FR-02/§6 的关键约定）：临时句同 ID 覆盖；定稿后冻结、迟到消息不改（旧连接迟到消息隔离前提）；空文本/乱序/重复容错。
4. 音频：48k 立体声 WAV → 16k 单声道 PCM（均值下混 + 重采样）；200ms/6400 字节分包；跨块重采样相位连续。
5. WebSocket 客户端：本地回环验证握手校验（Sec-WebSocket-Accept）、客户端掩码帧、ping→pong 自动应答、close 处理。
6. 隐私脱敏：dry-run 与错误输出不含 SecretKey、完整 SecretId、签名 URL。

## 已知缺陷与影响

- `resample_pcm16` 用线性插值，44.1k/48k → 16k 的抗混叠一般；mic 模式优先直接 16k 采集，重采样路径会打警告并要求人工评估音质（影响：可能轻微影响非 16k 设备的 CER，结果记录表需注明采样路径）。
- probe 的尾句等待固定 5s（FR-01 的 3s 是产品行为，M1 时按需求实现）。
- 官方文档内部对发包节奏有两种说法（接口要求 200ms、识别阶段 40ms）；工具默认 200ms（需求文档口径），40–200ms 可配置。
